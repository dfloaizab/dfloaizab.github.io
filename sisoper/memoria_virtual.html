¿Qué es la memoria virtual?

La memoria virtual es una técnica de gestión de memoria que permite a un proceso utilizar más espacio de memoria del que físicamente existe en la RAM. El sistema operativo crea la ilusión de un espacio de direcciones muy grande (usualmente 32 o 64 bits) al mantener en disco las partes del proceso que no se usan activamente, cargándolas a RAM bajo demanda.

Idea central

Solo las páginas o segmentos que se están ejecutando ahora mismo necesitan estar en RAM. El resto puede permanecer en disco. El SO gestiona qué partes están en memoria y cuáles no, de forma transparente para el proceso.

Beneficios principales

  • Permite ejecutar procesos cuyo tamaño supera la RAM disponible.
  • Facilita la multiprogramación: más procesos simultáneos compitiendo por la misma RAM física.
  • Proporciona aislamiento y protección entre procesos.
  • Simplifica la programación: cada proceso cree tener toda la memoria para sí.

Espacio de intercambio (swap space)

El espacio de intercambio (o swap) es una región del disco duro o SSD reservada para almacenar temporalmente las páginas o segmentos que el SO ha desalojado de la RAM para liberar espacio.

Operaciones clave

  • Page-out (swap-out): el SO mueve una página de RAM a disco y la marca como no presente en la tabla de páginas.
  • Page-in (swap-in): al acceder a una página no presente ocurre un page fault; el SO la carga del disco a RAM.

En Linux, el swap puede ser una partición dedicada o un archivo (swapfile). En Windows se denomina archivo de paginación (pagefile.sys).

Los 5 requisitos de la gestión de memoria

Stallings (Cap. 8) enumera de forma explícita cinco requisitos que cualquier esquema de gestión de memoria debe cumplir. Tanenbaum no los lista con los mismos cinco nombres, pero cubre los mismos problemas de fondo al hablar de espacios de direcciones y protección (Cap. 3). La memoria virtual los satisface todos:

1. Relocalización

Los procesos no saben en qué dirección física se cargarán. La MMU traduce en tiempo de ejecución la dirección lógica a la física real, así el proceso puede moverse en memoria sin recompilar.

2. Protección

Cada proceso accede únicamente a su propio espacio de direcciones. La MMU verifica en cada acceso los permisos de lectura, escritura y ejecución.

3. Compartición

Varios procesos pueden mapear la misma región física (p. ej. libc.so) sin romper la protección de cada uno.

4. Organización lógica

La memoria se organiza en unidades lógicas —páginas o segmentos— que el programador y el SO manejan de forma independiente.

5. Organización física

El SO decide la ubicación física de los datos (RAM o swap) de forma transparente; el programador no gestiona el disco manualmente.

Relocalización

Resuelve el problema de que un programa se compila con referencias a direcciones fijas, pero en tiempo de ejecución puede cargarse en cualquier lugar de la memoria física.

Con memoria virtual la relocalización es dinámica y continua: la tabla de páginas puede cambiar el mapeo en cualquier momento, por ejemplo al hacer swap de una página.

Protección

Cada entrada en la tabla de páginas lleva bits de protección. En x86-64, los más relevantes son:

BitNombreSignificado
PPresentPágina en memoria física
R/WRead/Write0 = solo lectura · 1 = lectura/escritura
U/SUser/Supervisor0 = solo kernel · 1 = accesible en modo usuario
NXNo-ExecuteProhíbe ejecutar código en esa página
DDirtyPágina modificada desde la última carga
AAccessedPágina accedida recientemente

Si un proceso intenta escribir en una página de solo lectura, la MMU lanza una excepción de protección antes de que el acceso llegue a ejecutarse.

Compartición

Permite que múltiples procesos accedan a los mismos marcos físicos, reduciendo el uso total de RAM. Casos de uso típicos:

  • Bibliotecas compartidas: libc.so, libpthread.so mapeadas en el espacio de muchos procesos.
  • Memoria compartida IPC: shmget() / mmap() en POSIX.
  • Copy-on-Write (CoW): tras fork(), padre e hijo comparten páginas hasta que uno escribe; solo entonces se duplica esa página.

Misma página física, permisos distintos por proceso — así una biblioteca compartida se ve de solo lectura para unos procesos y de lectura/escritura para otros, sin duplicar el contenido en RAM.

Direcciones lógicas (virtuales)

Una dirección lógica (o virtual) es la que genera la CPU al ejecutar instrucciones. Es la dirección que el proceso "ve" y usa; no corresponde necesariamente a una posición física en RAM. El compilador y el enlazador producen programas que usan exclusivamente direcciones lógicas.

Ejemplo para un sistema de 32 bits con páginas de 4 KB (2¹²): los 20 bits altos identifican la página lógica y los 12 bits bajos el desplazamiento dentro de ella.

Nota del profesor

En la práctica, una tabla de páginas de un solo nivel para 20 bits tendría 2²⁰ (más de un millón) de entradas por proceso — inviable en RAM. Por eso los sistemas reales usan tablas de páginas multinivel o invertidas (Stallings 8.1, Tanenbaum 3.3.4), que solo mantienen en memoria las ramas del árbol que el proceso realmente usa. Para efectos de este curso trabajamos con una tabla plana de una sola página lógica → un marco, que ilustra el mecanismo sin la complejidad adicional del árbol.

Direcciones físicas

Una dirección física es la ubicación real en la DRAM a la que accede el bus de memoria. La MMU la calcula a partir de la dirección lógica consultando la tabla de páginas:

dirección_física = (marco_físico × tamaño_de_página) + desplazamiento

TLB — Translation Lookaside Buffer

Para evitar consultar la tabla de páginas en RAM en cada acceso, la MMU incluye una caché asociativa llamada TLB. Si la traducción está en el TLB (TLB hit), la dirección física se obtiene en el orden de un ciclo de reloj — mucho más rápido que ir hasta RAM. Si no está (TLB miss), la MMU consulta la tabla de páginas en RAM y guarda el resultado en el TLB para el próximo acceso.

Flujo completo de un acceso a memoria virtual

1
La CPU genera una dirección lógica al ejecutar una instrucción.
2
La MMU busca la traducción en el TLB. Si hay hit, obtiene el marco físico directamente.
3
Si hay TLB miss, la MMU consulta la tabla de páginas en RAM.
4
Si la página no está en RAM (bit P=0), se genera un page fault (interrupción de hardware).
5
El SO toma el control: localiza la página en el swap, elige un marco libre (o aplica un algoritmo de reemplazo) y carga la página.
6
El SO actualiza la tabla de páginas y el TLB, luego retoma el proceso desde la instrucción que falló.
7
La MMU forma la dirección física = (marco × tamaño de página) + desplazamiento, y el acceso se completa.

Memoria virtual con paginación

La paginación divide el espacio lógico en bloques de tamaño fijo llamados páginas, y la memoria física en bloques del mismo tamaño llamados marcos. El SO mantiene una tabla de páginas por proceso.

Parámetros del ejemplo

  • Espacio lógico: 16 bits → 64 KB
  • Tamaño de página: 4 KB = 2¹²
  • Bits de página: 4 bits (16 páginas posibles)
  • Bits de desplazamiento: 12 bits
  • Memoria física: 32 KB → 8 marcos

Tabla de páginas del proceso P1

Pág. lógicaMarco físicoPresenteR/W
03✓R/W
17✓R only
2—✗ (en swap)R/W
31✓R/W

Ejemplo de traducción paso a paso

Dirección lógica: 0x3A4F (binario 0011 1010 0100 1111)

1
Separar: 4 bits de página + 12 bits de desplazamiento → página = 0011₂ = 3, desplazamiento = 0xA4F.
2
Consultar tabla: página 3 → marco 1, presente = ✓.
3
Calcular dirección física: 1 × 4096 + 0xA4F = 4096 + 2639 = 0x1A4F.
4
Acceso a RAM en la posición 0x1A4F. ✓

¿Qué pasa si accedemos a la página 2?

La página 2 tiene presente = ✗ (está en swap). La MMU genera un page fault. El SO lo maneja: carga la página del disco, asigna un marco libre, actualiza la tabla de páginas y retoma el proceso.

Memoria virtual con segmentación

La segmentación divide el espacio lógico en unidades de tamaño variable con significado semántico: código, datos, pila, heap, etc. Cada segmento tiene una base (dirección física de inicio) y un límite (tamaño máximo).

Tabla de segmentos del proceso P1

Seg.NombreBase físicaLímitePermisos

2Pila0x90000x0FFF (4095 B)R/W

Ejemplo de traducción paso a paso

Dirección lógica: (segmento = 1, desplazamiento = 0x200)

1
Extraer número de segmento: s = 1.
2
Consultar tabla de segmentos: segmento 1 → base = 0x1000, límite = 0x07FF.
3
Verificar límite: 0x200 ≤ 0x7FF ✓ (no hay violación).
4
Calcular dirección física: 0x1000 + 0x200 = 0x1200.
5
Acceso a RAM en la posición 0x1200. ✓

¿Qué pasa con desplazamiento = 0x900?

0x900 > límite 0x7FF. La MMU genera una excepción de segmentación (SIGSEGV en Unix). El SO termina el proceso o genera un core dump.

#define PAGE_SIZE       4096   /* Tamaño de página: 4 KB   */

#define NUM_FRAMES      8      /* Marcos físicos totales   */

/* ── Estructura de entrada en la tabla de páginas ────────
 * Cada entrada representa una página lógica del proceso.
 * Stallings, Fig. 8.8 | Tanenbaum, Fig. 3-11
 */
typedef struct {
    int  frame_number; /* Marco físico asignado (-1 si no está en RAM) */
    int  present;      /* 1 = en RAM, 0 = en swap / no asignada        */
    int  dirty;        /* 1 = página modificada (necesita swap-out)     */
    int  referenced;   /* 1 = accedida recientemente (para algoritmo reemplazo) */
    int  read_only;    /* 1 = solo lectura, 0 = lectura/escritura       */
} PageTableEntry;

/* ── Tabla de páginas (por proceso) ─────────────────────*/
PageTableEntry page_table[NUM_PAGES];

/* ── Mapa de marcos físicos ──────────────────────────────
 * frame_map[i] = 1 si el marco i está ocupado, 0 si libre
 */
int frame_map[NUM_FRAMES];

/* ── Estadísticas de acceso ──────────────────────────────*/
int total_accesses  = 0;
int page_faults     = 0;
int tlb_hits        = 0;  /* Simulado: si referenced==1 → "TLB hit" */

/* ── Prototipos ──────────────────────────────────────────*/

void  print_page_table(void);

/* ════════════════════════════════════════════════════════
 * FUNCIÓN: init_page_table
 * Inicializa la tabla de páginas: todas las páginas
 * comienzan sin asignar (not present).
 * ════════════════════════════════════════════════════════*/
void init_page_table(void) {
    int i;
    for (i = 0; i < NUM_PAGES; i++) {
        page_table[i].frame_number = -1;
        page_table[i].present      =  0;
        page_table[i].dirty        =  0;
        page_table[i].referenced   =  0;
        page_table[i].read_only    =  0;
    }
    memset(frame_map, 0, sizeof(frame_map));
}

/* ════════════════════════════════════════════════════════
 * FUNCIÓN: find_free_frame
 * Busca el primer marco físico libre.
 * Retorna: índice del marco libre, o -1 si no hay ninguno.
 * ════════════════════════════════════════════════════════*/
int find_free_frame(void) {
    int i;
    for (i = 0; i < NUM_FRAMES; i++) {
        if (frame_map[i] == 0) {
            return i;
        }
    }
    return -1; /* Sin marcos libres: necesita reemplazo */
}

     *   - Incluyan al menos una escritura en una página válida (dirty bit).
     *   - Accedan dos veces a la misma página para observar el TLB hit.
     *
     * Ejemplo:
     *   translate_address(0x5ABC, 0);
     *   translate_address(0x5DEF, 1);

    print_page_table();

Nota del profesor

Fíjense en el orden de las verificaciones dentro de translate_address(): la protección de escritura (Parte 1b) se revisa antes que la presencia en RAM. Eso no es casualidad — un acceso ilegal debe rechazarse sin importar si la página está cargada o no. Si invirtieran el orden, terminarían cargando en RAM (con su respectivo page fault) una página a la que de todas formas le iban a negar el acceso.

/* ── Constantes ─────────────────────────────────────────*/

#define MEM_SIZE        65536  /* Memoria física total: 64 KB     */

/* ── Permisos de segmento (bitmask) ─────────────────────*/
#define SEG_READ    0x01  /* Permiso de lectura  */
#define SEG_WRITE   0x02  /* Permiso de escritura */
#define SEG_EXEC    0x04  /* Permiso de ejecución */

/* ── Estructura de entrada en la tabla de segmentos ─────
 * Cada entrada describe un segmento lógico del proceso.
 * Stallings, Fig. 8.12 | Tanenbaum, Fig. 3-29
 */
typedef struct {
    unsigned long base;   /* Dirección física de inicio del segmento */
    unsigned long limit;  /* Tamaño máximo del segmento (en bytes)   */
    int           valid;  /* 1 = segmento válido/cargado, 0 = inválido */
    int           perms;  /* Bitmask de permisos: SEG_READ | SEG_WRITE | SEG_EXEC */
    char          name[16]; /* Nombre descriptivo (código, datos, pila...) */
} SegmentEntry;

/* ── Tabla de segmentos del proceso ─────────────────────*/
SegmentEntry seg_table[MAX_SEGMENTS];
int          num_segments = 0;

/* ── Estadísticas ────────────────────────────────────────*/
int total_accesses     = 0;
int seg_faults         = 0;   /* Accesos inválidos (offset > limit o seg inválido) */
int protection_errors  = 0;   /* Intentos de acceso sin permiso */

/* ── Prototipos ──────────────────────────────────────────*/

int   add_segment(unsigned long base, unsigned long limit, int perms, const char *name);

void  print_seg_table(void);
void  print_stats(void);

/* ════════════════════════════════════════════════════════
 * FUNCIÓN: init_seg_table
 * Inicializa la tabla de segmentos vacía.
 * ════════════════════════════════════════════════════════*/
void init_seg_table(void) {
    int i;
    for (i = 0; i < MAX_SEGMENTS; i++) {
        seg_table[i].valid = 0;
        seg_table[i].base  = 0;
        seg_table[i].limit = 0;
        seg_table[i].perms = 0;
        seg_table[i].name[0] = '\0';
    }
    num_segments = 0;
}

 *          o los parámetros son inválidos.

/* ════════════════════════════════════════════════════════
 * FUNCIÓN: print_seg_table — Imprime la tabla de segmentos.
 * ════════════════════════════════════════════════════════*/
void print_seg_table(void) {
    int i;
    printf("\n╔═══════════════════════════════════════════════════════════╗\n");
    printf("║            TABLA DE SEGMENTOS (proceso P1)                ║\n");

    for (i = 0; i < num_segments; i++) {
        printf("║  %d  ║ %-8s ║   0x%05lX   ║   0x%05lX   ║   %c%c%c     ║\n",
