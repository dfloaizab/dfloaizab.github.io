1. Recursión y divide y vencerásFundamento

Un algoritmo es recursivo cuando resuelve un problema en términos de instancias más pequeñas del mismo problema. Toda definición recursiva correcta necesita dos piezas: un caso base (detiene la recursión) y un paso recursivo que se acerque al caso base.

Por qué importa en árboles: un árbol es una estructura recursiva por definición (un nodo con un subárbol izquierdo y uno derecho, que a su vez son árboles). Por eso casi todas las operaciones sobre BST se escriben de forma natural y corta con recursión.

Divide y vencerás

  1. Dividir el problema en subproblemas más pequeños e independientes.
  2. Vencer: resolver cada subproblema recursivamente (o directamente si es trivial).
  3. Combinar las soluciones parciales en la solución final.
AlgoritmoDividirCombinarRecurrenciaCosto
Búsqueda binariaMitad del arregloNinguna (se descarta una mitad)T(n)=T(n/2)+1O(log n)
MergesortDos mitadesMezcla ordenada O(n)T(n)=2T(n/2)+nO(n log n)
QuicksortPartición por pivoteNingunaT(n)=2T(n/2)+n (prom.)O(n log n) / O(n²)
Búsqueda en BSTSubárbol izq. o der.NingunaT(h)=T(h-1)+1O(h)

Errores típicos: omitir el caso base (desbordamiento de pila, StackOverflowError), un paso recursivo que no converge y recalcular subproblemas repetidos sin necesidad.

2. Árboles binarios de búsquedaConcepto

Un árbol binario es una estructura jerárquica donde cada nodo tiene a lo sumo dos hijos. Un BST añade una invariante de orden:

Propiedad BST: para todo nodo con clave k, todas las claves del subárbol izquierdo son menores que k y todas las del subárbol derecho son mayores (o iguales, según la política de duplicados que se adopte).

Vocabulario

  • Raíz, hoja, padre, hijo, hermano.
  • Profundidad de un nodo: aristas desde la raíz.
  • Altura del árbol: aristas del camino más largo raíz–hoja (vacío = -1, un nodo = 0).
  • Nivel: conjunto de nodos con la misma profundidad.

Operaciones y costos

  • Insertar, buscar, mínimo, máximo: O(h).
  • Eliminar: O(h), con tres casos (hoja, un hijo, dos hijos → sucesor in-orden).
  • Con árbol balanceado h ≈ log n; degenerado h = n.

Eliminación: los tres casos

CasoAcción
Nodo hojaSe reemplaza por null.
Un solo hijoEl hijo ocupa el lugar del nodo eliminado.
Dos hijosSe copia la clave del sucesor in-orden (mínimo del subárbol derecho) en el nodo y se elimina el sucesor del subárbol derecho.

3. Recorridos y su elecciónDecisión de diseño

RecorridoOrdenCuándo usarlo
In-ordenIzq → Raíz → DerObtener las claves ordenadas ascendentemente (listados, validar un BST).
In-orden inversoDer → Raíz → IzqClaves en orden descendente; top-N con detención temprana.
Pre-ordenRaíz → Izq → DerCopiar o serializar el árbol (reconstruible); imprimir jerarquías.
Post-ordenIzq → Der → RaízLiberar o eliminar el árbol; calcular altura o tamaños (hijos antes que el padre).
Por niveles (BFS)Nivel a nivel, con colaImprimir por niveles, hallar el nivel de un nodo.
Poda: en una consulta por rango [min, max], solo se baja a la izquierda si min < clave y solo a la derecha si max > clave. La propiedad BST evita visitar ramas que no pueden contener resultados.

4. Forma del árbol y complejidadPeor caso vs. promedio

El costo de las operaciones depende de la altura, y la altura depende del orden de inserción. Insertar claves ya ordenadas produce un árbol degenerado, equivalente a una lista enlazada.

5. Árboles autobalanceadosConceptos esenciales

Un árbol autobalanceado mantiene su altura en O(log n) reajustando su estructura automáticamente tras inserciones y eliminaciones, mediante rotaciones que preservan la propiedad BST.

AVL

Para cada nodo, el factor de balance FB = altura(izq) − altura(der) debe estar en {-1, 0, 1}. Si tras una operación algún nodo llega a ±2, se rota:

CasoCondiciónCorrección
Izquierda–IzquierdaFB(nodo)=2, FB(izq)≥0Rotación simple a la derecha
Derecha–DerechaFB(nodo)=-2, FB(der)≤0Rotación simple a la izquierda
Izquierda–DerechaFB(nodo)=2, FB(izq)<0Rotación izquierda en el hijo, luego derecha en el nodo
Derecha–IzquierdaFB(nodo)=-2, FB(der)>0Rotación derecha en el hijo, luego izquierda en el nodo

Rojo-Negro y otros

  • Rojo-Negro: cada nodo tiene color; la raíz es negra, no hay dos rojos consecutivos y todo camino raíz–hoja tiene igual número de negros. Garantiza h ≤ 2·log₂(n+1). Rebalancea con menos rotaciones que AVL.
  • Árbol B / B+: nodos con muchas claves, bajo número de accesos a disco; base de bases de datos y sistemas de archivos.
  • Splay, Treap, AA: variantes con balance amortizado o probabilístico.
CriterioAVLRojo-Negro
BalanceMás estricto (h ≈ 1.44 log n)Más laxo (h ≤ 2 log n)
BúsquedaMás rápidaLigeramente más lenta
Inserción/eliminaciónMás rotacionesMenos rotaciones
Uso típicoLecturas frecuentes, índices en memoriaTreeMap/TreeSet de Java, planificador de Linux

6. Implementación y aplicaciones en JavaCódigo y uso real

Altura y consulta por rango (BST)

public int altura(Node n) {
    if (n == null) return -1;                       // caso base
    return 1 + Math.max(altura(n.getLeft()), altura(n.getRight()));
}

private void rango(Node n, int min, int max, ArrayList<Cliente> out) {
    if (n == null) return;
    if (min < n.getKey()) rango(n.getLeft(), min, max, out);   // poda izquierda
    if (min <= n.getKey() && n.getKey() <= max) out.add((Cliente) n.getValue());
    if (max > n.getKey()) rango(n.getRight(), min, max, out);  // poda derecha
}

Rotación a la derecha (AVL)

// y es el nodo desbalanceado (FB = 2); x es su hijo izquierdo
Node rotarDerecha(Node y) {
    Node x = y.getLeft();
    y.setLeft(x.getRight());   // el subárbol central pasa a y
    x.setRight(y);             // y baja como hijo derecho de x
    // actualizar alturas de y y luego de x
    return x;                  // x es la nueva raíz del subárbol
}

Aplicaciones

  • Índices de bases de datos (B+), consultas por rango y orden.

  • Árboles de expresión, compiladores y sistemas de archivos.

7. Ejercicio complementarioParte E · Extensión del ejercicio de clientes

Este ejercicio extiende la implementación del BinarySearchTree trabajada en el ejercicio de clientes. Debe entregarse el código completo y un documento breve con las respuestas escritas.

  1. Eliminación. Implemente Node eliminar(int key, Node root) con los tres casos. Pruebe eliminando una hoja, un nodo con un hijo y la raíz con dos hijos del árbol de compras.
  2. Sucesor y predecesor. Implemente sucesor(int key): el cliente con la menor clave estrictamente mayor. ¿Qué costo tiene y por qué no requiere recorrer todo el árbol?
  3. Validación. Escriba esBST(Node n, long min, long max) y pruebe con un árbol al que haya cambiado manualmente una clave. ¿Por qué comparar solo con el padre es insuficiente?
  4. Conteo y estadísticas. Implemente contar() (nodos), contarHojas() y promedioCompras(). Indique qué recorrido usó y por qué.
  5. Duplicados con lista. Rediseñe arbolEdad para que cada nodo guarde un ArrayList<Cliente>. Compare esta política con enviar iguales a la derecha: pérdida de datos, altura y costo de clientesEnRango.
  6. Rotaciones a mano. Inserte 10, 20, 30, 40, 50, 25 en un AVL, dibuje el árbol después de cada inserción, indique el factor de balance que dispara cada rotación y su tipo.
  7. Comparación empírica. Inserte 10.000 claves ordenadas y 10.000 aleatorias en su BST y mida la altura y el tiempo de 1.000 búsquedas. Repita con TreeMap y compare con las cotas teóricas.
  8. Reflexión. Para la tienda, ¿usaría BST simple, AVL o TreeMap? Justifique según tamaño de datos, orden de llegada y frecuencia de lecturas vs. escrituras.
Criterios sugeridos: correctitud de las operaciones (40 %), justificación del recorrido y de la complejidad (25 %), manejo de casos borde: árbol vacío, claves duplicadas (20 %), análisis empírico y reflexión (15 %).

8. Autoevaluación para el parcialHaga clic para ver la respuesta

Intente responder cada pregunta por escrito antes de abrir la solución. Las preguntas están agrupadas por tema.

Recursión y divide y vencerás

Concepto¿Qué elementos debe tener toda función recursiva correcta? ¿Qué ocurre si falta alguno?
Un caso base y un paso recursivo que se acerque a él. Sin caso base, la recursión no termina y se produce StackOverflowError; si el paso no converge, ocurre lo mismo.
AnálisisPlantee y resuelva la recurrencia de mergesort. ¿Por qué su costo es O(n log n)?
T(n) = 2T(n/2) + n. Hay log₂ n niveles de división y en cada nivel la mezcla cuesta O(n) en total, luego T(n) = O(n log n).
AnálisisExplique por qué la búsqueda binaria es divide y vencerás aunque no tenga paso de combinar.
Divide el problema a la mitad, resuelve solo una de las mitades y la solución de ese subproblema es directamente la solución global, por lo que combinar es trivial. T(n) = T(n/2) + O(1) = O(log n).

Árboles binarios de búsqueda

ConceptoEnuncie la propiedad BST. ¿Por qué comparar un nodo solo con su padre no basta para validar un BST?
Todas las claves del subárbol izquierdo son menores y todas las del derecho mayores que la clave del nodo. La restricción aplica a todo el subárbol, no solo a los hijos directos: un nodo puede respetar a su padre y violar a un ancestro. Se valida pasando un intervalo (min, max) en la recursión.
Recorridos¿Qué recorrido entrega las claves ordenadas? ¿Cuál usaría para los 3 mayores sin recorrer todo el árbol?
In-orden entrega orden ascendente. Para los mayores, in-orden inverso (der → raíz → izq) con un contador que detenga la recursión al reunir n elementos.
RecorridosDado el pre-orden 40, 20, 10, 30, 60, 50, 70 de un BST, dibuje el árbol y escriba su post-orden.
Raíz 40; menores (20, 10, 30) a la izquierda; mayores (60, 50, 70) a la derecha. Post-orden: 10, 30, 20, 50, 70, 60, 40.
DiseñoDescriba los tres casos de eliminación en un BST. ¿Por qué se usa el sucesor in-orden?
Hoja: se quita. Un hijo: el hijo lo reemplaza. Dos hijos: se sustituye su clave por la del sucesor (mínimo del subárbol derecho), que tiene a lo sumo un hijo, y se elimina ese nodo. El sucesor conserva la propiedad BST porque es mayor que todo el subárbol izquierdo y menor o igual que el resto del derecho.
Complejidad¿Cuál es la complejidad de buscar en un BST con n nodos en el mejor, promedio y peor caso? ¿De qué depende?
Mejor: O(1) (la clave está en la raíz). Promedio con inserciones aleatorias: O(log n). Peor: O(n), con árbol degenerado. Depende de la altura h, que depende del orden de inserción.
AplicaciónSi insertRecursive ignora claves iguales, ¿qué sucede al indexar clientes por edad? Proponga dos soluciones y compárelas.
Se pierden los clientes con edad repetida. Soluciones: (1) enviar iguales a la derecha: simple, pero la búsqueda halla solo uno y el árbol puede crecer en altura; (2) guardar una lista de clientes por nodo: no pierde datos, la búsqueda recupera todos y la altura depende de las claves distintas, a costa de un nodo más complejo.
AplicaciónEscriba el pseudocódigo de clientesEnRango(min, max) con poda e indique su costo.
Si el nodo es nulo, retornar. Si min < clave, recorrer izquierda. Si min ≤ clave ≤ max, agregar. Si max > clave, recorrer derecha. Costo: O(h + k), con k resultados.

Implementación en Java

CódigoUn setLeft está escrito como this.left = left con parámetro llamado newLeft. ¿Qué ocurre y por qué?
Asigna el atributo a sí mismo; el parámetro nunca se usa, así que el hijo no se enlaza y el árbol nunca crece.
Código¿Por qué insertNode debe hacer root = insertRecursive(...)?
En un árbol vacío, el método recursivo devuelve el nuevo nodo como raíz. Si no se asigna, root queda en null. En los demás casos devuelve la misma raíz, por lo que la asignación es inocua.
CódigoEscriba altura recursivamente. ¿Qué recorrido utiliza implícitamente?
if (n == null) return -1; return 1 + Math.max(altura(izq), altura(der)); Es un post-orden: necesita las alturas de los hijos antes de calcular la del nodo.

Árboles autobalanceados

Concepto¿Qué es el factor de balance de un AVL y qué valores admite?
Altura del subárbol izquierdo menos la del derecho. Debe valer -1, 0 o 1 en todos los nodos; si llega a ±2 se rota.
AnálisisUn nodo tiene FB = 2 y su hijo izquierdo FB = -1. ¿Qué rotación se aplica?
Caso izquierda–derecha: rotación a la izquierda sobre el hijo izquierdo y luego rotación a la derecha sobre el nodo.
AnálisisInserte 30, 20, 10 en un AVL vacío. ¿Qué ocurre y cuál es el árbol final?
Al insertar 10, el nodo 30 queda con FB = 2 (caso izquierda–izquierda). Rotación simple a la derecha: 20 es la raíz con hijos 10 y 30.
Comparación¿Cuándo preferiría AVL y cuándo rojo-negro?
AVL, con muchas lecturas y pocas modificaciones (balance más estricto, búsquedas más rápidas). Rojo-negro, con inserciones y eliminaciones frecuentes (menos rotaciones). Ambos garantizan O(log n).
Aplicación¿Qué estructura de Java usaría para clientes ordenados por edad con consultas de rango? ¿Cómo manejaría edades repetidas?
TreeMap (rojo-negro) con subMap para el rango. Para repetidos, Map<Integer, List<Cliente>>, pues un TreeMap no admite claves duplicadas.
Aplicación¿Por qué las bases de datos usan árboles B+ en lugar de AVL?
Cada nodo B+ contiene muchas claves y ocupa un bloque de disco, lo que reduce la altura y el número de accesos a disco; sus hojas enlazadas permiten recorridos por rango eficientes.

Glosario rápidoCierre

Altura
Número de aristas del camino más largo desde la raíz hasta una hoja.
Árbol degenerado
BST en el que cada nodo tiene un solo hijo; se comporta como una lista enlazada.
Factor de balance
Diferencia entre las alturas de los subárboles izquierdo y derecho de un nodo.
Rotación
Reorganización local de nodos que reduce la altura y preserva la propiedad BST.
Sucesor in-orden
Nodo con la menor clave mayor que la de un nodo dado.
